# Launch UI repair acceptance

Acceptance defined before implementation: public visitors and invited guardians
or drivers can find the real Android listing, clearly labelled as testing until
production publication is verified. iOS must say coming soon until a real listing
exists. No fabricated App Store link or claim of public availability. Native
sign-in remains focused on the installed app; administrator web sign-in continues
to enforce its current role restrictions.

Every supported role changing its own password receives actionable, approved
errors for current-password, policy and sign-in failures. Unknown server errors
remain generic; never expose raw server messages or passwords. Existing session,
current-password proof, MFA and security-event behavior must remain unchanged.

Administrator settings show useful names/statuses rather than internal UUIDs;
roster summaries use ordinary page wording; trip labels avoid repeating a named
direction. All role, authority/school, linked-student and own-driver boundaries,
notification choices and channels stay unchanged. Retired school-admin and
unsupported roles gain no new access.
