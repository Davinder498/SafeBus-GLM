# Web and Android appearance — 2026-10-26

## Implemented

- System, Light, and Dark, with System as the default. The browser preference
  uses `safebus.theme`, independently of sign-in and school authority settings.
  Android mirrors the preference in private native storage for startup.
- Dark canvas `#0F1720`, surfaces `#18232F`, raised surfaces `#223140`, main text
  `#E8EEF5`, secondary text `#A7B5C5`, and existing yellow `#FCD66B` for prominent
  headings, primary actions, and selected navigation. The wordmark is white.
- A shared blocking, content-hashed local startup script honors `script-src 'self'`.
  No security-policy exception or backend setting is needed.
- Shared semantic roles resolve existing Tailwind text/background/border utilities
  and variants. Native overrides preserve their original light values and use
  theme roles in dark mode. Form outlines, switches, dialogs, menus, and map
  controls have explicit dark treatments.
- Provider map tiles and attribution are unchanged. Print uses light colors and
  QR images retain their white backgrounds.
- Android DayNight resources include a white text-only splash wordmark. The
  appearance bridge synchronizes WebView backgrounds and system bars on startup,
  resume, configuration changes, and preference changes. The initial Android
  system-owned launch surface can follow the device theme before the app runs.
- CI runs the appearance browser suite. Shared theme configuration participates
  in Turbo cache inputs and Android release-source evidence; existing release
  approvals are not rewritten or bypassed.

## Validation

- `pnpm typecheck`, `pnpm lint`, `pnpm build`, and `pnpm test` passed locally.
- The appearance Playwright suite uses placeholder configuration, synthetic
  browser fixtures, and a local-only network boundary. It covers both themes,
  system changes, reload persistence, cross-tab changes, storage failures, public
  and authentication screens, all web administrator roles, guardian/driver
  settings, dropdowns, confirmation dialogs, print, and map popups/attribution.
  Axe checks cover the tested screens; this is not a claim of a complete manual
  accessibility audit. Inapplicable role/surface combinations are skipped.
- A production web build was served locally with the actual Netlify CSP. The
  saved dark preference loaded successfully with no uncaught browser errors.
- `:app:compileDebugJavaWithJavac` passed. The emulator-only
  `AppearanceInstrumentedTest` passed on Pixel 7 / Android API 36 with a
  placeholder frontend build: native persistence, activity restart, light/dark
  system-bar icons, and returning to System. The test guards against running
  against a non-emulator or a frontend without placeholder configuration.
- Android manual cold-start and device-theme-change attempts reached the correct
  app palettes, but launcher/System UI ANR dialogs interrupted screenshots on
  this host. Final native visual verification and physical-device testing remain
  release-review work. The emulator test does not certify a signed store bundle.
- Android publication/readiness regression checks passed, including rejection of
  release evidence after changing shared theme source.

## Release boundaries

This is implemented and locally tested work for review. It is not live-deployed
or store-published behavior. No hosted database, production fixture, account
permission, notification choice, billing rule, or provider configuration was
changed. Human merge approval and the protected web/Android release processes
remain required.

The pre-existing local Android Gradle settings and Play feature graphic were
preserved and excluded from this change.
